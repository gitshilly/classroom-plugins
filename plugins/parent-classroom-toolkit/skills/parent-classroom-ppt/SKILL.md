# 家长进课堂课件制作

让家长拿到能顺着讲的课件，页面、备注、TXT、互动与配套来自同一份逐页底稿。制作完成后接续 `$classroom-ppt-delivery`，不要只停在方案或生成脚本。

## 先确定入口

1. 读取当前项目AGENTS.md、用户已给资料及已有确认。明确本次是新课、整体改版还是局部修改。用户当次明确要求和当前项目规则优先。
2. 新课先读 [投入判断与共创](references/co-creation.md)，将上架前检查卡与四格合并：整理需求依据、投入与未知项，给出推荐，由用户决定是否推进；不重复填卡。**四格必须明确并等确认**：主题是什么；谁会买及实际使用场景；一句话真实记忆钩子；孩子最易参与的观察或动作。已明确信息带入核对，不把AI建议当批准。四格任一未确认，只讨论选题；不展开完整大纲、样张、PPT或商品素材。确认后保存 `选题四格卡.md`，可用 [模板](assets/选题四格卡模板.md)。
3. 既有课件局部修改和核对不重立项。锁定实际PPT路径、SHA256、允许变化及保留内容；扩内容不意味着可换画风。主题或购买者实质改变时重新对齐受影响四格。
4. 确认年级、时长、讲者身份和影响互动的设备/道具条件；只问缺失且影响结果的信息。明确约定优先；未另约定时默认以含互动和缓冲的30分钟以内为设计目标，并在框架中列明。不从历史样本猜定年级。
5. 教师公开课不套家长身份；读取项目相应教师规则。专属模板按用户选择执行。本技能不替换既有模板角色和母版。

## 制作顺序与确认

- 新课按“投入判断与四格确认 → 事实与课堂方案 → 整体框架确认 → 代表页验证/视觉确认 → 整套制作 → 实际渲染与验收交接”推进。现有框架和样张的明确批准有效，不重复索要、不逐页审批。
- 先读 [制作规范](references/production.md)。使用同一份 `课件工作单.json` 记录当前阶段、输入、证据、问题与下一允许动作，可复制 [工作单模板](assets/课件工作单_v0.4.json)。不为填满模板编造字段。
- 每页设计学习目标、真实观察线索、上屏文案、插图、参与方式、等待/操作、回应、揭晓、过渡与时间预算。框架包括独立第2页介绍和末页谢谢；未知姓名身份留空，不编造。
- 整体确认后用本课真实内容验证视觉：封面/场景、知识/观察、互动/应用功能均应有依据。已有适用样张可复用；所需代表页合并为一次视觉确认，不机械新增三页。
- 样张获准后连续制作整套，遇到内容冲突或重大范围/画风变化再对齐。用户仅要大纲或样张时停在所请求产物，不擅自扩成整套。

固定质量标准默认执行，不反复询问用户：视觉连贯且有变化、互动适龄且服务理解、知识服务主线、家长顺口能讲、控时含互动与缓冲、宣传用真实产品证明价值。AI主动给建议、追问关键缺口和修正常规问题；关键选题、课程取舍、框架/视觉方向及最终验收由用户决定。

## 读取与工具路由

在原项目存在时，视觉制作前读取 `docs/PPT视觉设计与审美自检规范.md`、`docs/小学趣味课堂PPT视觉设计增强规则.md`；确定视觉方案时读取 `components/成交款视觉参考库/README.md` 及适用分析，写清借鉴机制；完整质量复查读取 `docs/课堂课件质量复查与组件沉淀.md`。这些路径相对项目根目录，不写死某台电脑。

文件缺失时报告缺口并按随包规范继续适用工作，不能声称执行了缺失规则。课件实现使用当前可用的演示文稿技能/运行库，生成插画时使用图像生成技能；不固定技术栈。已有build-ppt-from-sources可辅助模式C，当前项目的四格、无机械20字上限、TXT与备课分离等规则优先于其旧默认；不要误入研究汇报的逐页审批模式。

## 候选成品与交接

交出实际可读PPTX、逐页备注、UTF-8上台TXT、独立《教案.docx》、备课与操作说明、课堂救场话术及实际需要的道具材料，以及最终PPT实际渲染的全部逐页图和带页码总览。教案为后续新课正式交付必备，结构和跨文件核对按 [制作规范](references/production.md)；明确只要大纲、样张或旧课局部修改时不擅自扩包。缺项如实记录。

在同一工作单保留用户确认依据、需求与投入未知项、课程取舍，以及候选PPT哈希、底稿与教案等附件路径、确认依据、渲染来源、修改范围及未检查项目，然后接续 `$classroom-ppt-delivery`。同一任务内接续不需另请用户批准；检查发现问题就返回该制作阶段并同步受影响文件。验收技能不可用时依 [制作规范末节](references/production.md) 完成适用核验并说明工具缺口。

旧产品不自动返工。制作授权不自动包含发布、发消息给买家或替换既有商品。
