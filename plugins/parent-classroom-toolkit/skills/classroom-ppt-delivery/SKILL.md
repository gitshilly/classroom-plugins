# 课堂课件验收与交付

接收实际课件与工作单，输出可追溯检查结果、明确问题、真实文件清单及获准范围内的交付物。只做用户授权的环节：只核验不自动改包，只要商品资料不重做课件。

## 入口与状态

读取当前AGENTS.md、指定PPT及同课工作单。新课制作交接沿用 `$parent-classroom-ppt` 的工作单；旧课检查锁定路径、版本、哈希与实际买家版本确认依据，不重新问四格。需要制作或修正内容时返回制作环节，保留已确认视觉。

分别记录文件、事实、图像、视觉、放映/可编辑性、控时估算、真实试讲和课堂效果。未检查、未实测、不适用都不能填通过；不适用注明理由。单个两页副本的结论不能移给整套在售版，文件通过也不能推出完整产品通过。

先读 [验收与工具](references/verification.md)。按需复制 [检查清单](assets/质量检查清单_v0.4.txt)；无需每次加载所有模板。

固定标准沿用已有确认并直接检查，不再问一遍偏好；AI检查结论与用户最终验收分开。新课交接核对合并四格卡与投入决定，既有课件不补立项手续。详细标准见 [验收与工具](references/verification.md)。

## 执行

1. 配对实际PPT、独立教案、TXT、底稿、逐页图、总览、附件和教学包。后续新课正式交付教案为必备（默认DOCX），核查末尾独立“课后反思与调整记录”及其真实性；旧课局部核对不自动补包，格式例外依据用户要求记录。旧版与新版各有相符文件时分开登记，不以文件夹名“最新/完整”猜版本。
2. 依据当次范围执行分项验收。事实、严重缺失、关键文字不可读和误导图像先修再交付；缺证据写明需要什么。用户明确跳过放映仅记录当次范围与替代检查；不把静态检测写成放映通过，不因此停止独立的流程研究。
3. 执行随包脚本或适配当前项目工具，产出真实报告。脚本并不覆盖全部质量维度；不能为了跑通而制造底稿、猜互动秒数或抹除差异。
4. 获准整理教学包时，在独立候选目录组装同版本文件，排除测试副本与内部记录；核对最终PPT哈希、全部页图/总览来源、备注/TXT与附件一致性，检查ZIP成员后再给出包。先保护旧文件，不自动替换在售版。
5. 每个问题记录页码/文件、表现、修改动作、返回阶段与复查结果。实际影响到内容时同步PPT、教案、备注、TXT、图、总览和有关展示；不批量改无关产品。

## 商品展示与反馈

只有涉及商品或笔记时读取 [展示与反馈](references/presentation-feedback.md)，并读取当前项目适用运营规则。宣传使用真实内页与实际功能；发布、买家联系和替换交付按用户授权处理。

反馈处理使用 [反馈修复单](assets/反馈与修复单_v0.2.json)，区分创作者偏好、文件检查、买家报告、真实课堂与假设。先定位版本和复现，再修正、复查和记录实际交付；没有买家反馈时不伪造闭环。

## 交付报告

给用户可读的结果、待处理问题和真实文件入口；内部机器报告另存。明确“检查的是哪版、哪些通过、哪些未覆盖、现在可继续什么”。先修复授权内可处理的问题，再交用户审阅；关键课程取舍和最终验收仍由用户决定。不要让用户必须理解JSON或运行命令才能得到结果。

此技能已包含经动物22页、植物18页文件配对验证的工具；这不是全链无人值守制课或已验证销售效果的承诺。项目规则缺失时说明缺口，使用随包规范完成适用检查，不宣称加载了不存在的文件。
